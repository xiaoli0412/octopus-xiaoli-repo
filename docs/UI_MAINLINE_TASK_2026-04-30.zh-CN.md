# UI 主线任务（2026-04-30）

## 唯一目标

在保留 `88eb9cc` 原版壳层、密度与页面节奏的前提下，完成 `AI Automation` 的独立能力中心重建，并继续维持首页、渠道、分组、模型/价格、设置页的既有主线约束。

本轮不改顶层路由结构，不重做全局导航，不把 AI 自动化拆成新的顶层页面；重点是把 `ai` 入口重建成一个成熟、可持续扩展的 MVP 工作台。

## 当前硬约束

- 首页保持原版顺序 `Total -> Activity -> StatsChart -> Rank`，并补 token / 渠道用量，不额外发明新首页结构。
- `Group` 与 `Model/Price` 桌面端按本轮新批注收敛为 3 栏；首页与渠道概括页仍是单栏例外。
- `Setting` 继续保留原版双栏瀑布流。
- `Channel` 二级菜单里的 `stats/overview` 必须单栏。
- `AI Automation` 本轮改为整页重建，采用 `单页内二级视图 + 单 AI 主链优先 + 右侧状态栏 + 固定高度工作区`。
- 每一批前端改动后，都必须同步 `web/out -> static/out`，不允许“源码变了但运行页没变”。

## AI 自动化重建口径

- 顶层路由仍为 `ai`，不新增顶层路由。
- 首屏只保留单 AI 主链：`任务类型 -> 输入 -> 执行模型/来源 -> 运行 -> 当前结果`。
- 右侧状态栏只保留高频状态：当前执行模型、来源模式、当前激活 Profile、学习状态、最近快照、最近任务。
- 页内二级视图固定为：`运行结果 / AI Profile / 多 AI 调度 / 模板与工具 / 历史与学习`。
- 所有长内容、列表、原始 JSON、学习样本、任务历史都必须在固定容器内滚动，不允许折叠撑高整页。
- 文案统一改成短句、客观句，不保留营销 hero、聊天式说明和大段 CardDescription。

## 本轮执行重点

1. 完成 AI 自动化页模块化拆分，收敛为页面壳、主链、状态栏、结果面板、Profile 面板、高级调度面板、学习面板、历史面板等稳定模块。
2. 保留现有后端 AI 自动化 API 与动态学习接口，只补前端结果消费契约，稳定支持 `摘要 / 对比 / 原始 / 工具执行 / Profile 产物 / 保护动作`。
3. 保留 `manual / ai_profile` 双来源保护链与非破坏式原则：允许生成 Profile、写快照、显式激活 Profile，不允许 AI 直接改底层渠道、分组、`group_items`、`priority`。
4. 多 AI 能力降级到二级“高级调度区”，保留 `split mode / dispatch mode / 并发数 / lane 模型覆盖 / lane 来源覆盖`，不新增新的后端 orchestration 协议。
5. 动态学习继续作为独立视图区，和设置页轻入口联动，但不再让设置页承担重控制台职责。
6. 补齐 `zh-Hans / zh-Hant / ja / en` 全量文案，消除 key path 泄漏、英文 fallback、乱码和混语。
7. 重写 AI 自动化前端测试与静态 smoke 守门，确保新结构下仍覆盖单 AI 主链、多 AI 调度、Profile 激活、学习区、历史区、脱敏 key 行为。
8. 统一版本与发布口径到 `1.19.1` / `v1.19.1`，并同步文档、构建注入和手工验收项。

## 页面验收方向

- 首屏必须表现为简洁单 AI 主链，不出现大面积说明块、折叠空白或左重右轻。
- 结果默认摘要视图，`对比 / 原始` 可切换。
- 生成 Profile 后可在结果区一键启用，但默认不自动切换运行来源。
- 多 AI 高级区可直接访问，但不能抢占首屏主路径。
- 学习、模板、工具、历史全部在固定容器内滚动。
- 中文界面无英文硬编码、无 key 泄漏、无乱码、无越界错行。
- 设置页入口与 AI 页面联动正常，设置页继续只承担轻入口角色。
