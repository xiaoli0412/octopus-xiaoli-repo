Critical: 设置导出 handler 存在未定义符号，后端当前工作区无法通过构建

internal/server/handlers/setting.go:105 调用了未定义的 includeSecrets。全仓搜索仅命中这一处，没有变量定义、常量声明或 query 解析逻辑。该问题会直接阻断 handlers 包编译，是当前最明确的发布阻塞。

High: stats_save_interval 在 UI 可改，但运行中的定时任务不会热更新

前端系统设置页允许修改统计落库周期，但后端只热更新 model_info_update_interval 和 sync_llm_interval。stats_save 任务仍然只在启动时注册一次，因此当前行为是“保存成功但运行时不生效”。

High: DynamicRoutingAdjustmentTask 更像摘要扫描，不像真实动态调节

该任务已注册进 runtime，但实现只统计 channel、group 和 key 分布并更新内存 summary，没有调整任何路由、阈值、缓存或配置。命名与文档表述都强于代码现实，属于典型“看起来实现了但主流程未接入”。

High: 动态路由预算与健康开关只有后端默认值，没有管理台配置入口

后端 settings 已新增 dynamic_routing_health_enabled 和多组 race_*_budget，但前端没有对等的 SettingKey 和设置模块。能力底座存在，但用户无法运营配置。

Medium: healthcheck 默认探测目标可能误报

cmd/healthcheck.go 将默认 server.host=0.0.0.0 直接拼成探活 URL。该地址适用于监听绑定，不适合作为客户端访问目标，默认情况下可能出现“服务正常但命令失败”的误导。

Medium: 熔断设置页轮询会覆盖未保存输入

SettingSystem 已做保护逻辑，但 SettingCircuitBreaker 每次轮询都会刷新 state。由于 settings 每 30 秒刷新一次，用户正在编辑但尚未保存的输入可能被后台轮询覆盖。

Low: 验证链存在覆盖错位

README 与 CI 都宣称具备完整验证链，但显式 Go 单测只覆盖 ./internal/op。这次最严重问题发生在 handler 层，说明当前验证策略不足以证明整个工作区可发布。
