Octopus 仓库完整审计

触发时间：2026-04-25T05:39:01+08:00 | 仓库：D:\GPT-codex\octopus_repo

结论：主流程真实可达，但当前工作区未通过关键 Go 回归验证，不能视为 release-clean。

Findings

CriticalCI 目标 Go 测试在 internal/op 稳定失败

  • 复现命令：go test ./internal/op ./internal/server/handlers ./internal/server/middleware ./internal/relay/... ./internal/task -count=1
  • 根因是测试契约与初始化链漂移：setupOpTestDB -> InitCache -> UserInit + settingRefreshCache
  • 直接症状包括 bootstrap admin 被意外导出，以及 setting 插入触发 UNIQUE constraint failed: settings.key

Criticalverify-go-env.ps1 会误报成功

  • 脚本执行 go test ./... / go build ./... 后未检查退出码
  • 本次脚本输出真实 FAIL，但整体退出码仍是 0
  • 这会污染本地审计、worklog 和人工回归结论

HighAI 任务取消存在竞态

  • AITaskCancel() 只改任务主状态，不收口步骤与后台执行
  • go test ./internal/server/handlers -run TestCancelAITaskHandlerMarksTaskCanceled -count=50 本次稳定复现失败
  • 失败时可见步骤仍为 running，并伴随 sql: database is closed / no AI model candidates available

Highmanual / ai_profile 仍是表层切换

  • 设置页会写 config_source_mode，后端会暴露 ActiveAIProfileID
  • 执行器只把这两个字段写进任务上下文 payload，没有据此切换真实运行配置来源
  • AI 页面真正执行时仍消费手工拼出的 effectiveBaseURL / APIKey / channelType / model

HighAI 任务配置快照不可持久恢复

  • config_snapshot 只放在进程内 sync.Map
  • 任务结束或进程重启后，原始 endpoint / key / model 快照会丢失
  • 这让任务难以真正回看、重试和恢复

Medium构建口径仍未统一到同一现实主线

  • README 仍写 pnpm run build
  • CI / release 与构建脚本已经统一到 build:static
  • Debian Dockerfile 仍走旧路径

Medium状态文档与当前实现漂移

  • CURRENT_STATUS_AND_PLAN.zh-CN.md 仍写 AI 自动化“代码实现未开始”
  • 实际仓库已经存在 migration / handler / op / executor / page / tests

Medium协议转换边界仍有真实 TODO

  • Anthropic 复杂 tool_result、Schema、Gemini json_schema、image generation request body 仍未完全收口
  • 主链路可用，但边角能力不能宣称已闭环完成

Low基础卫生问题仍存在

  • git diff --check 仍报 3 个前端文件 EOF 空行
  • 静态构建仍输出 baseline-browser-mapping 过期告警
